How it's built

The whole stack, layer by layer.

Every product I ship runs through four layers. I work on all of them, so the seams between them are mine too.

01 — Interface

What people touch.

Interfaces that stay quick when the data gets heavy. At Million Soft I cut page-load times by 30% with code splitting and lazy loading, and I still treat speed as part of the design.

Stack | Interface

React · Next.js · Vue · SvelteKit · Angular

02 — API

Where requests are judged.

The contract between screen and server is where most bugs are born. I write it down first, type it end to end, and keep it boring on purpose.

Stack | API

Node.js · NestJS · REST · TypeScript

03 — Services

Where the work gets done.

Workflows, content systems and low-code engines: the machinery that turns a request into a quote, a shipment or a published page. Split into services when it earns it, not before.

Stack | Services

Microservices · Workflows · CMS · Low-code

04 — Data

What must still be true tomorrow.

Schemas shaped around how the business actually works, so reports add up and records survive the next feature.

Stack | Data

PostgreSQL · MongoDB

Why the whole stack

Software rarely breaks at the surface. It breaks in the seams: where a button meets an endpoint, where an endpoint meets a table, where one team's assumption meets another's. I work across every layer so the seams are mine too. One person holding the whole shape of a system means fewer handoffs, fewer surprises, and products that keep working long after launch day.

How I work

Four rules that hold the layers together.

  1. 01

    Design the seams first.

    The contract between interface, API and database gets written before the code does. Most of the bugs never get a chance.

  2. 02

    Speed is a feature.

    Performance budgets from the first commit, not a rescue sprint at the end.

  3. 03

    Leave it legible.

    Code the next engineer can read without me in the room. Conventions, reviews, and docs that are actually true.

  4. 04

    Ship, then sharpen.

    Real users in production early. Real usage decides what gets polished next.
